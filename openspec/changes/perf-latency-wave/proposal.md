# Proposal — perf-latency-wave

## Problem
После серии фиксов конвейера остаются измеримые задержки и накладные расходы:
1. VAD системного звука в Rust — фиксированный RMS/Peak-порог: ложные срабатывания на шум и долгое ожидание конца речи; gap-таймеры сборщика вопросов консервативны (800мс + до 2x на mid-sentence).
2. Системный промпт LLM собирается в порядке, где волатильные блоки (язык, self-evolution) стоят в середине — префикс-кеш провайдеров (OpenAI/Anthropic/Groq) промахивается, TTFT растёт в 2+ раза.
3. Каждый 250мс аудиофрейм (16KB PCM) проходит IPC как JSON-массив чисел (~60-80KB текста на фрейм, парсинг V8 дважды на канал).
4. TLS-соединение к LLM открывается только после финализации вопроса (+150-350мс).
5. Перевод реплик запускается только для финализированного текста — парциалы висят со спиннером.
6. SQLite без WAL — синхронные блокирующие записи истории.

## Changes (human-readable, no implementation detail)
- Адаптивный VAD с плавающим noise-floor в Rust-захвате; укороченные таймеры тишины и gap-таймер сборщика.
- Стабильный порядок блоков системного промпта (статика вперёд, волатильность назад).
- Аудиофреймы через IPC — base64-строкой.
- Команда прогрева LLM-соединения, вызывается при начале речи.
- Дебаунс-перевод парциальных транскрипций в сабтитрах.
- WAL + PRAGMA-набор для базы на старте.

## Non-goals (deferred)
- Нативный WS-клиент Rust→ASR (R03i): новая зависимость + редизайн гейта — отдельная волна.
- Zustand-декомпозиция `app.context.tsx` (R07): рефакторинг 1037 строк — отдельная волна.
