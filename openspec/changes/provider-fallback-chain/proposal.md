# Proposal: фолбэк-цепочка провайдеров

## Зачем
Один провайдер = один источник сбоев на собесе: 429, таймаут, сеть — ответ
теряется, кандидат молчит. Ретрай того же ключа не помогает (тот же ключ,
та же сеть). Цепочка идёт дальше по списку.

## Что меняется
- `fetchAIResponse` принимает `allProviders?: TYPE_PROVIDER[]` (опционально —
  старые вызовы работают как раньше, один провайдер).
- Цепочка: `[selected, ...allProviders без selected]`. `useAIStreaming` и
  `useCompletionCommon` передают `allAiProviders` (уже есть в пропсах).
- Каждый кандидат идёт через тот же `streamAIResponse` (тот же trust-gate,
  тот же ключ-флоу). Внутренний 500мс ретрай 502/503/429/530 остаётся ВНУТРИ
  кандидата (блип чинится на месте, не дёргая цепочку).
- Любая ошибка кандидата (throw ИЛИ failure-чанк: `Network error`, `describeHttpFailure`,
  `Failed to parse`, trust-отказ, STALL, пустой стрим) → следующий.
  Аборт (`signal.aborted`) — НЕ фолбэк, тихий return (пользователь отменил).
- При переключении: yield `(переключаю на <имя>…)` + сброс накопленного
  (склейка двух half-ответов хуже честного рестарта).
- Исчерпание: `Все провайдеры недоступны (пробовали: A, B): <последняя>` —
  throw (не чанк: чанки-к-ответу уже не склеишь, а ошибка видна в UI).

## Не входит
- Приоритеты/веса в UI; health-чеки заранее; параллельный веер (стрим один);
  ретрай того же провайдера больше одного раза.

## Риски
- Двойная оплата: упавший после 3 чанков провайдер уже сжёг токены; новый
  начинает заново. Цена надёжности, видна в биллинге.
- Trust-gate на каждом кандидате отдельно: второй хост спрашивает снова —
  правильно (другой хост), но на собесе это диалог. Приемлемо: молчание хуже.
