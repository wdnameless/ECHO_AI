# Proposal: нормальное самообучение с одной кнопкой

## Зачем
Сейчас адаптация ответов под юзера — набор несвязанных механизмов с
доверенными дырами: пустой профиль уже врёт («Senior/TeamLead»,
confidence=1), фидбек пишется всегда, применяется везде независимо от
профиля, сброс чистит только половину хранилищ, а SQLite-половина —
мёртвый код (restore/loader никто не вызывает). Кнопки включения нет
вовсе: есть профиль-переключатель сценариев, который не решает «учиться
или нет». Пользователь просит: нормальный модуль + одна кнопка без
костылей.

## Что меняется
- **Профиль истины**: один `LearningProfile` (стиль + факты + правила),
  пустой профиль = пустой (никаких DEFAULT_FACTS в промпте).
- **Одна кнопка**: ВКЛ — записывает сигналы и применяет профиль;
  ВЫКЛ — не пишет и не применяет. Запись только из 👍/👎 и правок
  пользователя; пассивного сбора нет.
- **Влияние везде**: блок профиля применяется во всех путях ответов
  (интервью/беседа/лайвкод/чаты); языковое правило RU/EN выносится из
  evolution block и живёт всегда.
- **Прозрачность**: ручное редактирование правил/фактов, журнал «что
  выучено и почему», сброс чистит оба хранилища.
- **Доказательство**: набор эталонов «до/после» — один и тот же вопрос
  до фидбека и после; плюс регрессионные тесты на дрейф хранилищ.

## Не входит
- Новые провайдеры, векторная БД/эмбеддинги, облачная синхронизация,
  автообучение на всей истории, новые режимы.
- Оценка мок-интервью/скоринг, preflight аудио, CI gates — отдельные
  задачи.

## Риски
- Факты в промпте растут с каждым лайком: лимит объёма блока + обрезка
  старых записей (явное правило в спеке).
- Хранилища две штуки (localStorage sync + SQLite durable): инвариант
  «SQLite — истина, cache — производное» + тест на сброс обоих.
- Убрать DEFAULT_FACTS — поведение ответов изменится для всех, кто
  полагался на «Senior по умолчанию»: это и есть фикс, фиксируем в
  CHANGELOG-докке README.
