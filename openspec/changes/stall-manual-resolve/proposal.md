# Proposal: ручной разбор при STALL

## Зачем
Сейчас тишина провайдера 25с превращается в строку-ошибку внутри ответа
(а с P4 — в тихий авто-фолбэк на следующий). Кандидат не решает ничего:
ответ либо врёт строкой, либо уползает на другой провайдер. На собесе
это потерянные секунды и чужой ответ. Решение — за человеком, сразу,
без авто-таймаутов.

## Что меняется
- STALL-сигнал вместо ошибки: `streamAIResponse` при тишине 25с yield'ит
  сентинел `STALL_SENTINEL` (не текст!) и продолжает ждать дальше БЕЗ
  таймаута (голый `reader.read()`). Авто-сдачи больше нет вообще.
- P4-цепочка сентинел не трогает: форвардит наверх, фолбэк не включает,
  исчерпание не бросает. STALL — пауза, а не смерть кандидата.
- `useAIStreaming`: `isStalled` + `lastRequestRef` + три действия.
  `Ждать` = снять баннер (стрим и так ждёт), `Повторить` = тот же
  провайдер заново, `Другой` = one-off следующий по цепочке без смены
  глобального выбора + ссылка на выбор провайдера.
- Кнопки видны СРАЗУ во время обработки (тихий ряд под филлером), на
  STALL баннер становится prominent. Без клика — тишина, спиннер, R04.
- Mid-stall (контент был, потом тишина) — тот же сентинел вместо
  сегодняшнего молчаливого обрыва.

## Не входит
- Смена глобального провайдера из баннера; health-чеки; настраиваемый
  порог тишины в UI; авто-повтор по второму таймауту.

## Риски
- Бесконечное ожидание держит соединение: аборт (стоп/новый вопрос/
  unmount) закрывает как раньше. Зависший стрим без действий — цена
  ручного контроля, спиннер честно крутится.
- `reader.cancel()` при STALL больше не вызывается: pending `read()`
  висит до данных/аборта — так задумано (stall-guard: cancel всё равно
  не разблокирует Tauri-транспорт).
