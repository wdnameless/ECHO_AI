# Recon: «движок не отвечает» при здоровом движке + галлюцинация на тишине

## Reported
Красный баннер «Локальный движок распознавания не отвечает» с кнопками
«Перезапустить движок / Настроить», при этом версия в UI не менялась,
хотя сборка пересобиралась дважды.

## Измерено в момент жалобы
    /health         -> {"status":"ok", model tdt-0.6b-v3, Vulkan0, RTX 3060}
    stt_readiness   -> {"engine_running":true,"model_found":true,"reason":null}
    HTTP transcribe -> 200, {"text":"Yeah."}
Движок отвечал на каждый запрос — баннер был ложным.

## Root causes
1. **Тишина считалась отказом транспорта.** Движок отдаёт `{"text": ""}` на
   сегменте без речи (замерено: 100мс, 1с, 2с тишины → `""` c HTTP 200). Код
   превращал это в строку с `STT_ERROR_PREFIX`, а `transcribeWithFallback`
   читает префикс как отказ транспорта и бросает исключение → баннер.
2. **Тишина доходила до модели, и модель выдумывает слово.** 300мс цифровой
   тишины → `"Yeah."`, 12 прогонов подряд одинаково. Это слово и было видно в
   ленте как реплика собеседника. Rust VAD гейтит путь конца речи
   (`min_speech_chunks`), но TS-путь live-перетранскрипции несёт ещё и
   хвостовую тишину до порога конца речи.
3. **Версия не поднималась.** Предыдущие два коммита разворачивались без бампа,
   поэтому UI показывал 1.2.19 и правки выглядели отсутствующими.

## Fixes
- `stt.function.ts`: пустая расшифровка → `""`, без префикса ошибки.
- `stt-fallback.ts`: пустой результат не считается отказом движка.
- `useSystemAudioCapture.ts`: `hasSpeechEnergy` — речевой порог до вызова
  движка, по самому громкому окну ~100мс против `noise_gate_threshold`.
- Версия 1.2.19 → 1.2.20 в четырёх местах.

## Acceptance check
- 472 теста проходят, `tsc --noEmit` чисто.
- Невакуумность: возврат старого поведения → падает тест на тишину;
  гейт «всегда есть речь» → падает 5 из 7 тестов порога.
- В развёрнутой сборке 1.2.20: `appVersion = 1.2.20`, `versionInUi = v1.2.20`,
  `bannerShown = false`, гейт `H8` вызывается до сборки WAV.
