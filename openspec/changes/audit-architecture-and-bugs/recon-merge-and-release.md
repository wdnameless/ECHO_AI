# Recon: приземление 30 коммитов в master и выпуск 1.2.27

## Задача (дословно)
> Делай все по порядку

Порядок был объявлен ранее и выбран пользователем: 3 (PR + проверки) →
2 (тег и релиз) → 1 (слияние в master).

## Что сделано

1. **PR.** Существующий PR #28 покрывал все 30 коммитов, но описывал только
   первый. Заголовок и описание актуализированы: состав, проверки, честный
   список непокрытого.
2. **Blind oracle на весь диапазон** `master..HEAD`. Три прогона:
   - REJECT №1 — четыре регрессии, **все четыре мои**;
   - REJECT №2 — я перенёс эффект, но не обновил массив зависимостей и оставил
     старый комментарий, то есть заявил исправленное как исправленное ложно;
   - ACCEPT — регрессий нет, ложных утверждений нет, пропусков нет.
3. **Тег `v1.2.27`** запушен → CI запустился, job `check` отработал вживую:
   `Tag push (v1.2.27): releasing` → `should_release=true`.

## Что нашёл oracle (и это главная ценность)

| Регрессия | Чем подтверждена |
|---|---|
| `performSave` в cleanup дебаунс-эффекта → сохранение на каждое сообщение | замер: 3 быстрых обновления дали **2** записи вместо 0 |
| отмена таймера без flush → потеря реплики при короткой паузе | возврат фикса роняет тест |
| `checkImageSupport` без зависимости от списка провайдеров | `expected true to be false` при снятии |
| `ensure_server_running` в `setup()` → фриз UI до 12 с | код вызывается из главного потока |

Плюс два пропуска: одинаковый перевод (`Docker`, `123`) рисовался прочерком;
идемпотентность миграции 7 — проверил достижимость и задокументировал, почему
защита не нужна, вместо слепого добавления.

## Порядок тега и слияния

Тег выпущен **до** слияния намеренно: если сборка упадёт, `master` остаётся
чистым, а не получает непроверенный релиз.
