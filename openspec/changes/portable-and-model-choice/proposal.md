# Proposal: Портативная сборка, свои пути и выбор модели

## Why

Три связанные проблемы, обнаруженные при работе над доставкой приложения.

1. **Установщик весил 738 МБ, и 751 МБ из них — одна модель.** Модель
   распознавания лежала внутри бандла, поэтому «портативная версия» была
   невозможна: копирование одного `.exe` давало приложение, которое не слышит.
   Пользователь не мог ни выбрать модель, ни отказаться от неё.

2. **Все пути были зашиты в код.** `find_pluely_asr`, `find_model_path`,
   `open_sidecar_log_file` перебирали жёсткие кандидаты. Пользователь не мог
   положить модель на другой диск, указать уже имеющийся `.gguf` или вынести
   логи — при переполненном системном диске приложение просто не работало.

3. **Модель нечем было заменить.** В репозитории опубликовано шесть
   квантизаций с разным размером и точностью, но приложение умело ровно одну,
   ту, что внутри.

Дополнительно выяснилось, что `pluely-asr.exe` уже принимает `--model <path>`
и `PLUELY_ASR_MODEL`, то есть движку выбор модели безразличен — ограничение
было только в отсутствии UI и загрузчика.

## What Changes

1. **Портативная сборка.** Движок (`pluely-asr.exe` + 13 библиотек ggml,
   ~59 МБ) вшивается в исполняемый файл и распаковывается при первом запуске в
   каталог, имя которого выведено из содержимого сборки. Релиз публикует
   `Echo.AI_<версия>_portable_x64.zip` — это один `.exe` плюс маркер
   `.portable`. Установщик худеет до ~86 МБ.

2. **Пользовательские пути.** Один корень хранит движок, модели и логи; он либо
   задан пользователем, либо портативный (`ECHO_AI_HOME` или `.portable` рядом
   с exe), либо остаётся каталогом пользователя. Каждый подкаталог
   переопределяется отдельно. База данных намеренно не переезжает.

3. **Выбор и загрузка моделей.** Шесть квантизаций с размерами, SHA-256 и
   опубликованными WER; загрузка с Hugging Face по неизменяемой ревизии, с
   проверкой хэша и атомарной заменой. Пользовательский `.gguf` тоже
   выбирается.

4. **Запуск свёрнутым в трей** — настройка, а не поведение по умолчанию.

## Границы объёма

- **Не меняется**: имя бинарника, `identifier`, путь БД, `secure_storage.json`,
  канал обновлений, формат `latest.json`.
- **Вне этапа**: Linux/macOS-движок (встраивание сейчас только для Windows —
  на других платформах в наборе нет бинарника), докачка прерванной загрузки,
  удаление моделей по расписанию.
- **Принятый компромисс**: `.exe` вырос с 41 МБ до 86 МБ, потому что теперь
  содержит движок. Это цена за один файл вместо папки.

## Capabilities

- **Rust**: `settings.rs` (корни и пути), `models.rs` (каталог и загрузчик),
  `embedded.rs` (встраивание движка), `handy_server.rs` (разрешение путей).
- **Frontend**: `src/lib/storage/app-paths.ts`,
  `src/pages/settings/components/StorageSettings.tsx`.
- **Сборка**: `tauri.conf.json` (модель убрана из `resources`),
  `.github/workflows/release.yml` (шаг портативного архива, отказ от загрузки
  модели в CI).

## Verification

- Тесты: 24 Rust, 268 frontend, `tsc` чистый.
- Реальная сборка и запуск: движок распакован из exe, поднялся на
  Vulkan/RTX 3060, модель загружена из пользовательского каталога.
- Загрузчик прогнан против Hugging Face полностью: 495 МБ скачано, хэш
  совпал, повторный вызов не качает заново, временный файл не остаётся.
