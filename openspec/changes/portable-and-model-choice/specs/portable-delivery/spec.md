## ADDED Requirements

### Requirement: Один файл для запуска без установки

Приложение MUST запускаться из одного исполняемого файла, без установки и без
набора файлов рядом с ним. Движок распознавания речи MUST быть доступен после
первого запуска, не требуя от пользователя отдельных действий.

#### Scenario: Копирование одного файла даёт рабочее приложение
- **Given** пользователь скачал портативный архив и распаковал его в пустую папку
- **When** он запускает исполняемый файл
- **Then** приложение открывается, и движок распознавания доступен
- **And** файлы движка появляются внутри выбранного корня, а не рядом с exe

#### Scenario: Обновление сборки не использует чужие библиотеки
- **Given** в корне уже распакован движок предыдущей сборки
- **When** запускается новая сборка
- **Then** она распаковывает движок в отдельный каталог
- **And** прежний каталог удаляется, а не накапливается

#### Scenario: Прерванная распаковка не считается завершённой
- **Given** распаковка движка была прервана
- **When** приложение запускается снова
- **Then** распаковка выполняется заново, а неисправный набор не используется

### Requirement: Портативный режим

Приложение MUST поддерживать режим, в котором все его файлы (движок, модели,
логи, настройки) находятся в одной папке, пригодной для переноса.

#### Scenario: Портативная папка переносима
- **Given** приложение работает в портативном режиме
- **When** папку копируют на другой носитель и запускают оттуда
- **Then** настройки, движок и выбранная модель доступны
- **And** приложение не обращается к каталогу пользователя за ними

#### Scenario: Режим переключается из интерфейса
- **Given** приложение установлено обычным образом
- **When** пользователь включает портативный режим
- **Then** приложение раскладывает свои файлы рядом с собой
- **And** выключение режима возвращает прежнее расположение

### Requirement: Пользователь задаёт расположение файлов

Пути к движку, моделям и логам MUST определяться пользователем, а не быть
зашитыми в приложение.

#### Scenario: Каталоги задаются по отдельности
- **Given** пользователь открыл настройки хранилища
- **When** он указывает отдельный каталог для моделей
- **Then** движок и логи остаются в прежнем месте
- **And** новые модели сохраняются в указанный каталог

#### Scenario: Недоступный для записи каталог отклоняется заранее
- **Given** пользователь выбрал каталог моделей без права записи
- **When** он применяет настройку
- **Then** приложение сообщает об этом сразу
- **And** загрузка модели не начинается и не проваливается в середине

#### Scenario: Движок запускается из указанного каталога
- **Given** пользователь сменил каталог движка
- **When** приложение запускает распознавание
- **Then** используется бинарник из указанного каталога

### Requirement: Выбор и загрузка модели распознавания

Приложение MUST предлагать опубликованный каталог моделей распознавания и
скачивать выбранную, а также использовать файл модели, предоставленный
пользователем.

#### Scenario: Пользователю виден весь каталог
- **Given** пользователь открыл настройки моделей
- **When** список построен
- **Then** в нём присутствуют все опубликованные семейства, доступные движку
- **And** для каждой модели показаны точность, скорость, число языков и WER
- **And** модели, которые движок не умеет загружать, не предлагаются

#### Scenario: Каталог не расходится с публикацией
- **Given** каталог встроен в сборку
- **When** он сравнивается с опубликованными данными
- **Then** размеры и SHA-256 каждого файла взяты из листинга
- **And** ревизия каждого репозитория зафиксирована коммитом, а не веткой

#### Scenario: Квантизация выбирается отдельно
- **Given** у модели несколько квантизаций
- **When** пользователь выбирает конкретную
- **Then** скачивается именно она
- **And** выбор по умолчанию отмечен

#### Scenario: Модель скачивается с проверкой целостности
- **Given** пользователь выбрал модель в списке
- **When** загрузка завершается
- **Then** файл проверяется по опубликованному SHA-256
- **And** при несовпадении файл не принимается и сообщается об ошибке

#### Scenario: Ход загрузки виден
- **Given** загрузка модели началась
- **When** она выполняется
- **Then** интерфейс показывает прогресс и объём
- **And** остальное приложение остаётся отзывчивым

#### Scenario: Повторная загрузка не выполняется
- **Given** модель уже скачана
- **When** пользователь выбирает её снова
- **Then** файл переиспользуется, повторная загрузка не запускается

#### Scenario: Своя модель тоже доступна
- **Given** пользователь положил собственный `.gguf` в каталог моделей
- **When** он выбирает его
- **Then** движок перезапускается на этом файле

#### Scenario: Смена модели вступает в силу
- **Given** движок работает с одной моделью
- **When** пользователь выбирает другую
- **Then** движок перезапускается и сообщает о готовности
- **And** при неудаче пользователь видит причину, а не молчание

#### Scenario: Удаление не выходит за пределы каталога моделей
- **Given** запрос на удаление содержит путь за пределами каталога моделей
- **When** он обрабатывается
- **Then** удаление отклоняется

#### Scenario: Возможности модели не выдумываются
- **Given** выбранная модель не поддерживает потоковую выдачу
- **When** она загружена движком
- **Then** приложение знает об этом заранее, а не обнаруживает при запросе

### Requirement: Готовность распознавания сообщается честно

Если модель отсутствует или движок не запущен, приложение MUST сообщать об
этом и указывать, что именно нужно сделать.

#### Scenario: Первый запуск без модели
- **Given** приложение запущено впервые и моделей нет
- **When** пользователь открывает настройки хранилища
- **Then** он видит объяснение и предложение скачать рекомендованную модель
- **And** распознавание не выглядит просто «выключенным»

### Requirement: Запуск свёрнутым в трей

Пользователь MUST иметь возможность запускать приложение без появления окна,
с доступом через значок в трее.

#### Scenario: Тихий запуск
- **Given** включена настройка запуска свёрнутым
- **When** приложение стартует
- **Then** главное окно не показывается
- **And** значок в трее доступен и открывает окно

### Requirement: Поставка больше не содержит модель

Установщик и портативная сборка MUST NOT включать файл модели распознавания.

#### Scenario: Сборка без модели
- **Given** выполняется сборка релиза
- **When** проверяются поставляемые файлы
- **Then** файла модели среди них нет
- **And** сборка не скачивает модель из сети
