# Proposal: in-place обновление портативки из zip

## Зачем
Портативная копия держит всё рядом с exe (`.echo-ai/`: модели, настройки,
движок). Кнопка обновления ставила MSI в системный каталог — новая копия
стартовала пустой, пользователь видел "закрылся и версия старая". Предупреждение
чинит информированность, но не проблему: in-place пути не было вообще, потому
что `latest.json` не содержал zip как цель обновления.

## Что меняется
1. **CI** (`release.yml`): tauri-action публикует в `latest.json` ключ
   `windows-x86_64-portable` с url на `Echo.AI_<ver>_portable_x64.zip` и его
   подписью. Подпись: `tauri-action` подписывает все `archives`; если нет —
   fallback-шаг `tauri signer sign` по `TAURI_SIGNING_PRIVATE_KEY`.
2. **Фронт** (`Updater` + `UpdateSettings`): если `useIsPortable()` —
   скачать zip по URL из апдейта, распаковать поверх exe-dir через
   `@tauri-apps/plugin-fs` (исключить `.echo-ai/`), затем `relaunch()`.
   Иначе — прежний `downloadAndInstall()`.
3. **Текст** `PortableUpdateNotice`: "Обновление заменит файлы приложения,
   данные в `.echo-ai` сохранятся".

## Не входит
- Дельта-обновления, фоновая загрузка, откат на предыдущую версию.
- macOS/Linux portable (там нет portable-раскладки).
- Смена формата архива: exe + `.portable` как сейчас.

## Риски
- Распаковка поверх запущенного exe на Windows: файл заблокирован ОС.
  Митигация: распаковка во временную папку рядом + скрипт-заменщик через
  `plugin-process Command` (cmd /c move после выхода) либо требование закрыть.
  Выбрать по факту теста на Windows.
- Подпись zip: без неё updater отвергнет цель. Проверить `latest.json` после
  первого релиза с ключом.
