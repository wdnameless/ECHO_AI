# Proposal: S3 — Честное состояние лицензии и гейты сборки

## Why
Аудит (2026-09-14) показал, что механизм лицензирования не просто заглушён, а обходится по трём независимым путям, а фронтенд принимает это состояние за истину:

1. `src-tauri/src/activate.rs:306-312` — `validate_license_api` не выполняет сетевого вызова, константно возвращает `is_active: true` с датой `2099-12-31`.
2. `src-tauri/src/shortcuts.rs:40` — `LicenseState::default()` инициализирует `AtomicBool::new(true)`, то есть состояние разрешающее до любого обращения фронтенда.
3. `src-tauri/src/shortcuts.rs:504-508` — `set_license_status(app, _has_license)` игнорирует переданный флаг и принудительно пишет `true`.
4. `src-tauri/src/api.rs:1127-1130` — `check_license_status` считает лицензию валидной по факту существования файла `secure_storage.json`, без проверки ключа.

Дополнительно: `src-tauri/src/shortcuts.rs:651-657` — гейт `move_window` завязан на `LicenseState`; при корректной инициализации это заблокирует перемещение окна, то есть наивное «починить дефолт на `false`» сломает базовую функцию для всех без лицензии.

Пользователь выбрал модель: **платежи — заглушка**, но состояние лицензии должно быть честным, а поведение гейтов зависеть от типа сборки («Dev — всё открыто, Release — гейты»).

## What Changes
1. **Честный дефолт**: `LicenseState` инициализируется неактивным; `set_license_status` уважает переданный флаг.
2. **Отсутствие фиктивного успеха**: `validate_license_api` не возвращает константное `is_active: true`. Без серверной валидации тариф считается Free — явно, а не по умолчанию.
3. **Разделение гейтов по сборке**: в dev-сборке все возможности доступны (для разработки и собственного использования); в release Pro-возможности закрыты. Один признак сборки, без сюрпризов.
4. **Развязка базовых функций от лицензии**: перемещение окна и прочие базовые действия не должны зависеть от тарифа. Гейт `move_window` снимается.
5. **Заглушка оплаты обозначена как заглушка**: экран апгрейда честно сообщает, что оплата недоступна, вместо имитации рабочей покупки.

## Capabilities & Impact
- **Capabilities affected**: `licensing`, `feature-gating`.
- **Rust**: `src-tauri/src/shortcuts.rs` (LicenseState, set_license_status, гейт move_window), `src-tauri/src/activate.rs` (validate_license_api), `src-tauri/src/api.rs` (check_license_status).
- **Frontend**: `src/contexts/app.context.tsx` (`getActiveLicenseStatus`, `hasActiveLicense`), `src/lib/functions/pluely.api.ts` (кэш 30 с), `src/components/GetLicense.tsx`.
- **Риски регрессии**: 12 фич, сейчас закрытых `hasActiveLicense`, изменят доступность; перемещение окна перестаёт зависеть от лицензии; дашборд-аналитика и хостируемый API должны корректно обрабатывать отсутствие лицензии.
- **Не затрагивается**: SQL-доступ, CSP, брендинг, реальные платежи.

## Verification
- Юнит-тесты Rust: `LicenseState::default()` неактивен; `set_license_status(false)` не активирует; `set_license_status(true)` активирует.
- Тест отсутствия фиктивного успеха: `validate_license_api` при недоступном сервере не возвращает активную лицензию.
- Тест развязки: перемещение окна работает при неактивной лицензии.
- Смоук: dev-сборка — все возможности доступны; release-сборка — Pro-возможности закрыты, Free работают.
