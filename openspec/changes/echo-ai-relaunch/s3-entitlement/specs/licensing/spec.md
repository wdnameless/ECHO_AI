## ADDED Requirements

### Requirement: Честное состояние лицензии по умолчанию

Состояние лицензии MUST инициализироваться неактивным и MUST отражать переданное значение, а не принудительно разрешающее.

#### Scenario: Состояние по умолчанию неактивно
- **Given** приложение только запустилось и лицензия ещё не проверена
- **When** запрашивается состояние лицензии
- **Then** состояние неактивно

#### Scenario: Переданное значение уважается
- **Given** фронтенд передаёт в бэкенд состояние лицензии
- **When** передано неактивное состояние
- **Then** состояние остаётся неактивным
- **And** при передаче активного состояния оно становится активным

### Requirement: Отсутствие фиктивной валидности

Проверка лицензии MUST NOT сообщать об активной лицензии без действительной проверки. При недоступности серверной валидации тариф MUST считаться бесплатным.

#### Scenario: Нет серверной валидации — тариф Free
- **Given** серверная валидация лицензии недоступна
- **When** приложение определяет доступные возможности
- **Then** возможности, отнесённые к Pro, недоступны
- **And** бесплатные возможности работают полностью

#### Scenario: Наличие файла не подтверждает лицензию
- **Given** файл хранилища существует, но ключ лицензии недействителен или отсутствует
- **When** проверяется состояние лицензии
- **Then** лицензия не считается активной

### Requirement: Поведение гейтов зависит от типа сборки

В dev-сборке все возможности MUST быть доступны; в release-сборке Pro-возможности MUST быть закрыты.

#### Scenario: Dev-сборка открывает все возможности
- **Given** приложение собрано в режиме разработки
- **When** пользователь открывает Pro-возможность
- **Then** возможность доступна без лицензии

#### Scenario: Release-сборка закрывает Pro-возможности
- **Given** приложение собрано в релизном режиме и лицензия не активна
- **When** пользователь открывает Pro-возможность
- **Then** возможность недоступна и предлагается апгрейд

#### Scenario: Release-сборка сохраняет бесплатные возможности
- **Given** приложение собрано в релизном режиме и лицензия не активна
- **When** пользователь запускает диктовку, режим встречи, локальное распознавание, работу со своим ключом или открывает историю чатов
- **Then** все эти возможности работают без ограничений

### Requirement: Развязка базовых функций от тарифа

Базовые функции приложения MUST NOT зависеть от состояния лицензии.

#### Scenario: Перемещение окна не требует лицензии
- **Given** лицензия не активна
- **When** пользователь перетаскивает окно
- **Then** окно перемещается

### Requirement: Заглушка оплаты обозначена честно

При отсутствии работающего платёжного механизма интерфейс MUST сообщать об этом явно и MUST NOT имитировать успешную покупку.

#### Scenario: Экран апгрейда не имитирует покупку
- **Given** платёжный механизм не подключён
- **When** пользователь открывает экран апгрейда
- **Then** интерфейс сообщает, что оплата недоступна
- **And** не выполняется переход на нерабочий платёжный адрес
