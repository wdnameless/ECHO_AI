# Аудит автономности: от чего зависит приложение

Проверка по запросу «чтобы мы ни от чего не зависели, и у нас было одно цельное приложение, которое мы билдим».

## Итог

Приложение **уже собирается в один бинарник** — внешних сервисов, без которых оно не работает, нет. Но есть четыре зависимости, которые влияют на сборку и на работу отдельных функций, и одна из них ломала автономность по-настоящему.

## 1. Распознавание речи: автономно (Python не обязателен)

Порядок запуска в `ensure_server_running` (`src-tauri/src/handy_server.rs:388-404`):

1. `spawn_pluely_asr()` — нативный движок `pluely-asr.exe`
2. только если он не найден → `find_python()` и запуск `handy_stt_server.py`

**Вывод:** Python — резервный путь, а не обязательный. `pluely-asr.exe` бандлится в установщик (4.9 МБ, есть в `CHECKSUMS.sha256`). Если Python не установлен, приложение просто печатает `python not found, skipping` и работает на нативном движке.

**Что не идеально:** Python-скрипт всё ещё бандлится (`tauri.conf.json:51`), хотя нужен только как резерв. Это не ломает автономность, но добавляет вес и путаницу.

## 2. Модель ASR: скачивается при сборке (717 МБ)

- `.gitignore:35-38` исключает `*.gguf` из репозитория
- `tauri.conf.json:52` — `resources/**/*` **включает** модель в бандл
- `.github/workflows/release.yml:61-64` — CI скачивает её с HuggingFace по зафиксированному коммиту

**Вывод:** для сборки нужен доступ к HuggingFace. Рантайм-зависимости нет: у конечного пользователя модель уже внутри. Скачивание идёт по immutable-хэшу снапшота, поэтому воспроизводимо.

## 3. Установленные исправления

### 3.1. Захардкоженный путь к машине разработчика — **исправлено**

Было два места:
- `handy_server.rs:176` — кандидат поиска модели `D:\WORK\Pluely fork\models\...`
- `handy_server.rs:306` — **запасное значение** при ненайденной модели

Второе опаснее: если модель не найдена, движок молча пытался открыть путь с чужой машины и падал с невнятной ошибкой. Теперь при отсутствии модели — честный отказ с сообщением в лог.

### 3.2. Перевод зависел от Google GTX — **исправлено**

Google отдавал **429** на каждый запрос, а код возвращал оригинальный текст, не пробуя запасной сервис. Теперь порядок: локальный прокси → MyMemory → Google как резерв. Проверено:
`«Раз два, раз два, проверка связи»` → `«One two, one two, communication check»`.

Запрос идёт через Rust-мост, а не из WebView: строгая CSP из S1 ограничивает `connect-src` локальными адресами.

## 4. Остаточные зависимости (не влияют на автономность)

| Зависимость | Где | Оценка |
|---|---|---|
| PowerShell | TTS `speak_text` (`handy_server.rs:516`) | Встроен в Windows, отсутствием не грозит. Вызывается только режимом mock-interview и озвучкой филлеров |
| HuggingFace | сборка (`release.yml:61`) | Только этап сборки; пин по хэшу |
| Приватный GitHub-репозиторий | скачивание sidecar при сборке | **требует токен**; связано с R25 |
| AI-провайдеры, MyMemory, Google | рантайм по выбору пользователя | Пользователь выбирает сам; локальные модели (Ollama/LM Studio) работают без интернета |

## 5. Вывод по «одному цельному приложению»

Требование выполняется: `npm run tauri build` даёт `pluely.exe`, внутри которого фронтенд, Rust-бэкенд, движок ASR, DLL рантайма и модель. Никакой установки Python, Node или отдельных сервисов конечному пользователю не требуется.

Что стоит решить отдельно:
- **Python-скрипт в бандле** — можно убрать, оставив только нативный движок
- **Модель в git-истории** — 717 МБ качаются при каждой сборке из CI
- **Канал обновлений** (R25) — упирается в приватность репозитория, а не в автономность
