## ADDED Requirements

### Requirement: Реестр доверенных хостов

Приложение MUST вести реестр хостов, которым разрешено получать сетевые запросы с учётными данными пользователя. В реестр по умолчанию входят localhost и хост выбранного провайдера.

#### Scenario: Хост настроенного провайдера доверенный
- **Given** пользователь выбрал AI-провайдера с известным хостом
- **When** выполняется запрос к этому провайдеру
- **Then** запрос отправляется без дополнительного подтверждения

#### Scenario: Локальный хост доверенный
- **Given** приложение обращается к локальному сайдкару или локальной модели
- **When** выполняется запрос на `127.0.0.1` или `localhost`
- **Then** запрос отправляется без дополнительного подтверждения

### Requirement: Подтверждение для незнакомого хоста

Запрос на хост вне реестра доверенных MUST требовать явного подтверждения пользователя до отправки учётных данных.

#### Scenario: Незнакомый хост вызывает подтверждение
- **Given** curl-шаблон или настроенный провайдер адресует хост вне реестра доверенных
- **When** пользователь инициирует запрос
- **Then** отображается подтверждение с указанием хоста-получателя
- **And** запрос не отправляется до решения пользователя

#### Scenario: Подтверждённый хост запоминается
- **Given** пользователь подтвердил доверие хосту
- **When** выполняется следующий запрос к этому хосту
- **Then** повторное подтверждение не запрашивается

### Requirement: Защита учётных данных от отправки на чужой хост

Учётные данные (API-ключи, токены авторизации) MUST NOT передаваться на хост вне реестра доверенных без явного согласия пользователя.

#### Scenario: Отказ пользователя предотвращает утечку ключа
- **Given** запрос адресован хосту вне реестра доверенных
- **When** пользователь отказывается доверять хосту
- **Then** заголовки авторизации и ключи не отправляются на этот хост

#### Scenario: Подмена хоста в шаблоне не утекает молча
- **Given** существующий curl-шаблон был изменён так, что указывает на другой хост
- **When** пользователь инициирует запрос
- **Then** смена хоста обнаруживается и требует подтверждения
- **And** ключ не уходит на новый хост без ведома пользователя

### Requirement: Сохранение работоспособности кастомных провайдеров

Контроль исходящих запросов MUST NOT делать неработоспособными пользовательские curl-провайдеры: незнакомый хост обрабатывается подтверждением, а не отказом.

#### Scenario: Пользовательский провайдер работает после подтверждения
- **Given** пользователь создал собственный AI-провайдер с curl-шаблоном на собственном хосте
- **When** он подтверждает доверие этому хосту
- **Then** запросы к провайдеру выполняются штатно
