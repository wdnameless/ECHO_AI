# Design: S2 — Контроль исходящих запросов и защита ключей

## Инвентарь точек отправки

Проверка всех вызовов `tauriFetch` (`@tauri-apps/plugin-http`) в коде:

| Файл:строка | Несёт секрет | Закрыт шлюзом |
|---|---|---|
| `src/lib/functions/ai-response.function.ts:533` | `Authorization`, `x-api-key` из curl-шаблона | да |
| `src/lib/functions/stt.function.ts:256-258` | `Authorization`, `xi-api-key` из curl-шаблона | да |
| `src/lib/functions/models.function.ts:200` | `Authorization: Bearer <ключ>` | да |
| `src/lib/web-search.ts:100,136,171` | ключи Brave/Exa/Tavily | нет — S4 (перенос в keychain) |
| `src/lib/fast-translator.ts:80` | только `User-Agent`, фиксированный хост Google | шлюз не нужен |
| `src/pages/dev/components/ai-configs/Providers.tsx:419` | нет секретов (проверка пользователем) | шлюз не нужен |

**Вывод:** три точки несут ключи пользователя и получают URL из пользовательских curl-шаблонов — все три закрыты шлюзом. Веб-поиск (свой фиксированный хост на каждый сервис) относится к S4.

## Решение 1: реестр доверенных хостов

`src/lib/trusted-hosts.ts`.

Доверенные хосты формируются из трёх источников:

1. **Локальные** — `localhost`, `127.0.0.1`, `0.0.0.0`: сайдкар ASR, Ollama, LMStudio.
2. **Встроенные провайдеры** — хосты извлекаются из их же curl-шаблонов при инициализации модуля (`extractKnownProviderHosts`). Это исключает дублирование списка доменов: единственный источник — сами константы провайдеров. Собрано 17 хостов.
3. **Подтверждённые пользователем** — хранятся в localStorage под ключом `trusted_hosts`.

**Защита от обхода суффиксом:** сравнение идёт по точному hostname (через `URL`), а не по подстроке. `api.openai.com.evil.example` не проходит — на это есть отдельный тест.

**Шаблонные хосты:** если host содержит `{{VAR}}` (например `{{REGION}}.stt.speech.microsoft.com`), извлечение возвращает `null` — статически доверенным такой хост объявить нельзя, он пройдёт обычный путь подтверждения.

## Решение 2: шлюз подтверждения, fail-closed

Запросы к AI-провайдерам стриминговые: блокирующий диалог посреди потока недопустим. Подтверждение запрашивается **до** отправки, шлюз (`src/lib/host-trust-gate.ts`) возвращает решение промисом.

Исходы:

| Решение | Заголовки | Хост запоминается |
|---|---|---|
| доверенный хост | без изменений | — |
| «Доверять и отправить» | без изменений | да |
| «Отправить без ключа» | `Authorization`, `x-api-key`, `api-key`, `xi-api-key`, `openai-api-key` удалены | нет |
| «Отмена» | запрос не отправляется | нет |
| обработчик диалога не зарегистрирован | запрос не отправляется | нет |

Последняя строка — ключевая: без UI-моста запрос не уходит. Отсутствие диалога не превращается в молчаливую утечку ключа.

В диалог передаются **только имена** заголовков, значения — никогда. На это есть тест.

Связь сетевого слоя с React: модуль вне дерева, поэтому подписка `setHostTrustPrompt(handler)` вместо пропсов. `HostTrustProvider` держит один pending-запрос и резолвит его решением пользователя.

## Решение 3: сужение capability — невозможно без потери кастомных провайдеров

**Отвергнуто после проверки исходников плагина.**

`tauri-plugin-http-2.5.2`:

- `src/lib.rs:29` — в `setup` регистрируется только `Http` (cookie jar). Публичного `scope()`/`scope_mut()` нет.
- `src/commands.rs:182-217` — scope собирается **заново на каждом вызове** `fetch` из `CommandScope<Entry>` + `GlobalScope<Entry>`, то есть целиком из статических ACL-файлов.
- Для сравнения: `tauri-plugin-fs-2.4.2/src/lib.rs:367-381` даёт `impl FsScope` с runtime-доступом. У http-плагина аналога нет.

Следствие: **расширить scope для подтверждённого хоста в рантайме технически невозможно** без форка плагина. Поэтому сужение `http:default` до статического списка несовместимо с R07: пользовательский провайдер на своём хосте получил бы отказ на уровне ACL **до** того, как шлюз показал бы диалог.

**Принято:** ACL не сужается, защита на уровне приложения. R05/R06/R08 закрыты шлюзом, R07 сохранён.

**Остаточный риск:** wildcard `http://**` остаётся вторым слоем. XSS из S1 закрыт, поэтому для эксплуатации нужна другая уязвимость. Зафиксировано как отложенное.

## Тестирование

`src/lib/__tests__/trusted-hosts.test.ts` — 13 тестов: извлечение хоста из curl (включая `--url` и шаблонные хосты), доверие localhost и встроенным провайдерам, отказ произвольному хосту, защита от суффиксного обхода, персистентность списка, идемпотентность.

`src/lib/__tests__/host-trust-gate.test.ts` — 8 тестов: отсутствие утечки значений в диалог, fail-closed без обработчика, отказ не отправляет ключ, «без ключа» удаляет только секретные заголовки, «доверять» запоминает хост и не переспрашивает.
