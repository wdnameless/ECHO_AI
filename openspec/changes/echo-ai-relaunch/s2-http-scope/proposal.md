# Proposal: S2 — Контроль исходящих запросов и защита ключей

## Why
Аудит (2026-09-14) выявил, что исходящие HTTP-запросы из приложения не ограничены и могут унести секреты на произвольный хост:

1. `src-tauri/capabilities/default.json:31-32` и `src-tauri/capabilities/cross-platform.json:30-31` — `{"url": "http://**"}`, `{"url": "https://**"}`: HTTP-плагину разрешён весь интернет.
2. `src/lib/curl-validator.ts:12-21` — проверяет только префикс строки `curl`, не ограничивая хост и схему.
3. `src/lib/functions/ai-response.function.ts:532` — любой URL, содержащий `http`, уходит в `tauriFetch`, то есть запрос выполняется из Rust в обход CORS WebView, с заголовками `Authorization`/`x-api-key` из шаблона.
4. `src/pages/dev/components/ai-configs/CreateEditProvider.tsx` — пользователь создаёт произвольный curl-шаблон через UI; это штатная возможность, а не аномалия.

Следствие: импортированный или вредоносный curl-шаблон отправляет API-ключ пользователя на чужой хост. Это SSRF и утечка учётных данных (CWE-918, CWE-522).

## What Changes
Пользователь выбрал модель **«Подтверждение при незнакомом хосте»** — она сохраняет работоспособность кастомных провайдеров, не открывая молчаливую утечку ключей:

1. **Реестр доверенных хостов**: формируется из выбранного провайдера (его host) + localhost-порты сайдкаров. Хосты, подтверждённые пользователем, запоминаются.
2. **Перехват перед отправкой**: если запрос уходит на хост вне реестра, показывается диалог подтверждения с явным указанием, какой хост получит запрос и какие секреты будут к нему отправлены.
3. **Блокировка секретов без согласия**: если пользователь отказался, запрос выполняется без заголовков авторизации либо не выполняется вовсе — вместо молчаливой отправки ключа.
4. **Сужение capability**: wildcard `http://**`/`https://**` заменяется на явный список провайдерских доменов + localhost, а произвольные хосты открываются через runtime-scope после подтверждения (механизм подтверждён: `tauri-plugin-http-2.5.2/src/commands.rs:182` — `GlobalScope<Entry>`).

## Capabilities & Impact
- **Capabilities affected**: `network-egress`, `secret-handling`.
- **Frontend**: новый `src/lib/trusted-hosts.ts`, `src/lib/functions/ai-response.function.ts`, `src/lib/functions/stt.function.ts`, `src/lib/curl-validator.ts`, новый диалог подтверждения в `src/components/`.
- **Rust**: `src-tauri/src/lib.rs` (настройка scope), `src-tauri/capabilities/*.json`.
- **Риски регрессии**: существующие кастомные провайдеры (пользователь увидит диалог один раз на хост), локальный сайдкар STT, Ollama/LMStudio на localhost.
- **Не затрагивается**: SQL-доступ, лицензии, брендинг.

## Verification
- Юнит-тесты: извлечение хоста из curl-шаблона; классификация «доверенный / требует подтверждения»; отсутствие заголовков авторизации при отказе.
- Тест реестра: хост текущего провайдера доверенный; localhost доверенный; чужой хост требует подтверждения.
- Смоук в приложении: запрос к настроенному провайдеру проходит без диалога; шаблон с подменённым хостом вызывает диалог и не отправляет ключ при отказе.
