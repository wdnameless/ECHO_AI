# Portable updater boundaries and ownership

## Frontend owner — UpdaterFrontend
Own src/components/updater/PortableUpdateNotice.tsx, src/components/updater/index.tsx, src/pages/settings/components/UpdateSettings.tsx, updater tests only. Preserve visual layout. Keep useIsPortable for notice display; it is not authoritative for selecting a package. Change checkForUpdateForLayout(): Promise<Update|null> to await getPaths and then call check(target portable or default); unknown layout rejects. Migrate all callers. Export installUpdateForLayout(update: Update, onEvent?: (event: DownloadEvent)=>void): Promise<boolean>: true means existing caller should relaunch (installed updater); false means native portable helper owns restart. Resolve paths again at install; never use stale rendered boolean. Portable uses invoke('install_portable_update', {expectedVersion:update.version, onEvent: Channel<DownloadEvent>}); event names/data identical to Tauri updater. No caller-supplied URLs/paths/public key.

## Native owner — UpdaterNative
Own src-tauri/src/portable_update.rs (new), src-tauri/src/lib.rs, src-tauri/src/main.rs, src-tauri/Cargo.toml, Cargo.lock and native updater tests/fixture harness only. Register install_portable_update(app: AppHandle, expected_version: String, on_event: tauri::ipc::Channel<DownloadEvent>) -> Result<(),String>. Re-resolve native portable layout; on non-Windows or installed layout reject, never downgrade. app.updater_builder().target('windows-x86_64-portable').build()?.check().await? must match expectedVersion and be newer. Reuse Update.download for signature verification before archive parsing. ZIP 4.3.0 already exists in Cargo.lock; promote it as a direct dependency only if needed, minimal features, offline lockfile update; no new packages/credentials.

Accept only bounded root payload (one Echo AI.exe/current expected app executable and optional .portable marker), reject traversal/symlinks/reparse/excess entries/data files/unbounded decompression. Copy only the verified executable to an isolated staging directory on the executable filesystem. Preserve existing executable name and data tree. Helper mode runs before Tauri initialization via main.rs and a narrow exported native entry; stock updater install_inner is never used for portable. Wait for the parent process to exit, perform same-volume swap with old executable backup and rollback on move/spawn failure, relaunch the same filename/folder. Constrain helper arguments/staging/target so it cannot overwrite arbitrary paths. Serialize concurrent update starts. Return concrete hardware-free real-helper smoke command using temporary fixture executables/data; no real user app installation/exit.

## Release owner — UpdaterRelease
Own .github/workflows/release.yml and narrowly necessary release validation/fixture scripts/tests. Remove --write-signature-file, reuse npm-ci-installed CLI; signer emits .sig normally. Validate archive shape (root executable and .portable marker), require nonempty signature, upload ZIP and sig before publishing manifest referencing them. Make new release publication/draft-to-latest promotion the last successful step; installed assets remain supported. No release/version bump/push in this task. Fixtures ephemeral .tmp/OS temp only, no human keys.

## Integration owner
Own this change's docs/spec/manifest, README update after smoke, integrations, final build/test/runtime proof, review gates and commit. Specialists do not run builds/tests/lint/formatters mid-flight. Tests are written but run once after integration. Each slice returns STATUS | FILES(paths only) | TESTS(unrun/planned exact commands) | INTERFACES | REQUIREMENTS R## | CONCERNS, at most 25 lines. Changes paths are absolute under the supplied worktree; current agent cwd may be a retired audio directory, so use explicit absolute paths and bash cwd.
