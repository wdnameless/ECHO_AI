fix(asr): answer one interviewer utterance once; speak the filler in the question's language

Two user-visible defects:

1. Duplicate answers / spurious interruptions. The batch path measured the
   pause between fragments by ARRIVAL time, but the recogniser returns text
   ~1.1s after the speech and each fragment covers seconds of audio - so a
   300ms mid-sentence breath looked like a 3s silence. The assembler then
   treated the remainder of one question as a fresh question, discarded the
   text already transcribed, and the second request aborted the first
   mid-stream. The capture layer now measures the pause between the VAD's own
   events and passes it on the fragment; the arrival interval is only the
   fallback.

   A second duplicate path is gone: handleBatchInterviewerTranscription armed
   the auto-ask manager on the SAME text the assembler had already timed,
   producing one dispatch per fragment plus one per utterance.

2. Filler language. Only Russian openers existed, so an English question was
   answered with "Слушайте, да, это отличный вопрос". ENGLISH_FILLERS added and
   selected by the script of the question (Cyrillic vs Latin, no model call).
